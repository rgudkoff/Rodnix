# Подсистема памяти: проект переписывания

Составлено 23 августа 2026 по `~/dev/freebsd-src` и `~/dev/xnu`.
Предшествующий разбор границы MI/MD — `mm_architecture.md`, он остаётся в силе
и здесь не повторяется.

## Тезис

**Оперативная память — не склад, а ресурс задержки.** Свободная память сама по
себе не ценность: хороший менеджер держит её занятой полезным — кэшем страниц,
разделяемым кодом, горячими данными — но умеет быстро и **предсказуемо** отдать
её интерактивной работе.

Для ОС креаторов это означает порядок, а не лозунг:

```
сначала отзывчивость и аудио
затем открытые проекты
затем производительность фонового рендера
кэши и воспроизводимые данные — первые кандидаты на возврат
```

И влияет это на VM не через «особый аллокатор для художников», а через четыре
вещи: **возврат памяти с учётом класса обслуживания, честный учёт, уведомления
о давлении, безопасное восстановление проекта.**

## Две независимые оси

Их путают чаще всего, а проектировать надо по обеим.

**Цена возврата** — сколько стоит забрать страницу:

| | стоимость |
|---|---|
| чистая, есть на диске | отдать даром |
| воспроизводимая (объявлена volatile) | выбросить, ввода-вывода нет |
| грязная анонимная | записать в своп, миллисекунды |

**Цена ошибки** — кто пострадает, если забрать именно эту: поток аудио или
фоновый рендер.

XNU покрывает первую ось purgeable-объектами, вторую — полосами jetsam **на
процесс**. Нам нужны обе, и вторая **на объект**, потому что у одного
приложения оба вида памяти одновременно: кольцевой буфер аудио двигать нельзя
никогда, а история отмен того же приложения — законный кандидат на выброс.
Полоса на процесс этого не различает.

## Что берём из референсов

**Аудио выше переднего плана** — не наша выдумка.
`bsd/sys/kern_memorystatus.h`:

```c
#define JETSAM_PRIORITY_BACKGROUND                30
#define JETSAM_PRIORITY_FOREGROUND               100
#define JETSAM_PRIORITY_AUDIO_AND_ACCESSORY      120
#define JETSAM_PRIORITY_CRITICAL                 190
```

**Воспроизводимые данные как структура, а не как намерение.**
`osfmk/mach/vm_purgable.h`: объект объявляется volatile, и ядро вправе его
страницы **выбросить, а не выгрузить** — `NONVOLATILE` / `VOLATILE` / `EMPTY`,
плюс восемь групп приоритета выброса и FIFO/LIFO внутри группы. Приложение
обнаруживает `EMPTY` и пересоздаёт данные. Для кэшей это качественно лучше
свопа: ноль ввода-вывода при возврате и ноль места в свопе.

**Класс реального времени в самой странице.** `osfmk/vm/vm_page.h`:
`vmp_realtime:1`, «page used by realtime thread», ставится в `vm_fault.c` когда
отказ пришёл от потока с `sched_mode == TH_MODE_REALTIME`, и
`vm_pageout_protect_realtime` не даёт демону такую страницу забрать. На уровне
объекта — `for_realtime`.

**«Грязная, нужен ввод-вывод» — отдельная очередь, а не проверка.** У FreeBSD
четыре: `PQ_ACTIVE`, `PQ_INACTIVE`, `PQ_LAUNDRY`, `PQ_UNSWAPPABLE`
(`sys/vm/vm_page.h`).

**Контракт `pmap`** — 52 функции в `sys/vm/pmap.h`, непрозрачный `pmap_t`,
страница как `vm_page_t`, права как `vm_prot_t`. Замок — `pm_mtx` **внутри**
`struct pmap`, то есть на адресное пространство.

**Уведомления о давлении** — `NOTE_MEMORYSTATUS_PRESSURE_NORMAL/WARN/CRITICAL`.

## Что мы делаем не так сейчас

Измерено, не по памяти. MI-слой 1230 строк, MD-слой 2850.

1. **`pmap_t` нет.** 37 обращений к `PTE_*`/`pml4_phys`/`paging_*` прямо в `mm/`.
2. **`vm_map` — массив на 128 записей с линейным поиском.** Жёсткий потолок и
   O(n) на каждом отказе.
3. **`vm_object.resident_pages` — плоский массив физических адресов** размером с
   объект: отображение гигабайта это 2 МБ индекса, и в нём только адрес.
4. **`vm_page_t` нет вообще.** Счётчики ссылок живут в боковой таблице
   `vm_page_ref`, отдельно от страницы.
5. **Один глобальный `vm_lock`** на весь слой.
6. **Классов, очередей, возврата, учёта и уведомлений нет** ни в каком виде.
7. **Дескрипторы страниц молча пропадают**, если не влезли в первые 16 МБ
   (`pmm_setup_page_descs`); на 4 ГБ их нет вовсе.

## Решения

### Носитель класса обслуживания

- **объект** — основной носитель;
- **процесс** — задаёт значение по умолчанию для своих объектов;
- **поток** — при отказе повышает класс страницы, если он реального времени.

```c
typedef enum {
    VM_CLASS_RT = 0,      /* закреплена, не возвращается и не выгружается */
    VM_CLASS_PROJECT,     /* открытый проект: своп только под критическим давлением */
    VM_CLASS_NORMAL,      /* обычная анонимная */
    VM_CLASS_CACHE,       /* чистая, есть на диске: выбросить, ввода-вывода нет */
    VM_CLASS_VOLATILE,    /* воспроизводимая: выбросить объект целиком */
} vm_class_t;
```

Порядок возврата — снизу вверх: `VOLATILE` → `CACHE` → `NORMAL` → `PROJECT`.
`RT` не возвращается никогда; если её не хватает, выделение отказывает, а не
забирает.

### Реальное время: сильное обещание

Слабое обещание — «страницы потока реального времени не вытесняются» (путь
XNU) — даёт вероятность, а не границу. Мы берём сильное: **поток реального
времени не берёт отказ страницы вообще.** Память закрепляется и отображается
заранее, до того как поток объявит себя реальным временем.

Это дороже для приложения — надо заранее сказать, сколько памяти, — но это
единственное, что даёт границу сверху. И это согласуется с уже сделанным:
измеритель задержек (`latency_hygiene.md`) существует ровно для того, чтобы
такие границы можно было проверять, а не заявлять.

### Своп: пригодность объявляется, а не выводится

Страница из свопа стоит чтения с диска — миллисекунды. Для аудио это смерть,
для рабочего набора фонового рендера — норма. Поэтому пригодность к свопу
следует из класса, а не из возраста по LRU. Для всего, к чему прикасался поток
реального времени, значение по умолчанию — «никогда».

### Учёт: два числа, потому что они отвечают на разные вопросы

**Начисленное.** За разделяемую страницу платит **каждый держатель**. Сумма
по процессам будет больше физической памяти — это принято сознательно: число
отвечает на вопрос «чем пользуется этот процесс», а не «сколько всего занято».

**Освобождаемое.** Страницы, для которых этот процесс — последний держатель,
плюс его грязная анонимная память.

Второе число нужно потому, что **процесс, у которого вся память разделяемая,
при убийстве не освобождает ничего.** Убивать по начисленному — значит
регулярно убивать не того. XNU приходит к тому же с другой стороны:
`phys_footprint` у них не RSS, а разложение на `internal`,
`purgeable_nonvolatile`, `alternate_accounting`, `iokit_mapped`, `page_table`
(`bsd/kern/kern_memorystatus.c`).

### Когда память кончилась, а сотрудничать некому — убиваем по полосам

Полоса на процесс, как jetsam. Внутри полосы выбор по **освобождаемому**, не по
начисленному — как XNU сортирует внутри полосы по footprint, а не по RSS.

Обязательные свойства, иначе это не политика, а произвол:

- убийство **всегда объяснено**: полоса, причина, сколько освободило;
- перед убийством — уведомление о давлении, с окном на реакцию;
- ядро и его резерв не участвуют: страницы `RT` и ядра вне игры;
- **окно на сброс.** Доля VM в «безопасном восстановлении проекта» ровно одна:
  не потерять страницы раньше, чем приложение успеет их записать. Всё
  остальное в восстановлении — договор приложения и файловой системы, и в ядро
  ему не место.

## Структуры

### `vm_page`

Один структ на физическую страницу, массив по номеру кадра. Физический адрес
**не хранится** — он выводится из индекса, потому что наш массив плотный на
`[memory_start, memory_end)`; FreeBSD хранит его из-за разреженных сегментов,
которых у нас нет.

```c
struct vm_page {
    struct vm_object* object;      /* чей я (O) */
    uint64_t          pindex;      /* смещение в объекте, в страницах (O) */
    TAILQ_ENTRY(vm_page) q;        /* очередь или список свободных (Q) */
    uint32_t          ref_count;   /* (A) */
    uint16_t          wire_count;  /* закреплена, если > 0 (Q) */
    uint8_t           queue;       /* ACTIVE/INACTIVE/LAUNDRY/FREE/NONE (Q) */
    uint8_t           order;       /* порядок приятеля, когда свободна (F) */
    uint8_t           klass;       /* vm_class_t (O) */
    uint8_t           flags;       /* dirty, referenced, busy, rt (O,A) */
    struct md_page    md;          /* машинно-зависимое, своё на архитектуру */
};
```

Пометки в скобках — замок, под которым поле живёт, по образцу
`sys/vm/vm_page.h`. Это не украшение: именно эти пометки делают выяснение
«чем защищено поле» чтением, а не расследованием.

`struct md_page` **внутри** машинно-независимой структуры — так же, как у
FreeBSD. Верхний слой владеет структурой, каждый pmap получает в ней
непрозрачное место.

Цена: около 48 байт на страницу, ~1.2% памяти. Приемлемо.

### `pmap`

Непрозрачный тип, замок внутри. Все `PTE_*` собираются только здесь.
Минимальный контракт первого этапа:

```c
pmap_t   pmap_create(void);
void     pmap_destroy(pmap_t);
int      pmap_enter(pmap_t, vm_offset_t va, vm_page_t m, vm_prot_t, unsigned flags);
void     pmap_remove(pmap_t, vm_offset_t start, vm_offset_t end);
void     pmap_protect(pmap_t, vm_offset_t, vm_offset_t, vm_prot_t);
vm_paddr_t pmap_extract(pmap_t, vm_offset_t va);
void     pmap_activate(pmap_t);
void     pmap_zero_page(vm_page_t);
void     pmap_copy_page(vm_page_t src, vm_page_t dst);
```

Полный список FreeBSD — 52 функции; остальное добавляется по мере надобности,
а не заранее.

### `vm_object`

Резидентные страницы — не плоский массив, а разрежённая структура (начнём с
хеша по `pindex`, при необходимости заменим на дерево). Свой замок. Класс
обслуживания, состояние purgeable, счётчик ссылок, тип и пейджер.

### `vm_map`

Сортированная структура вместо массива на 128, без потолка. Замок **на карту**,
спящий: путь отказа делает ввод-вывод, а спинлок под вводом-выводом — это то,
что мы уже чинили в другом месте.

### Очереди

`ACTIVE`, `INACTIVE`, `LAUNDRY` (грязная, нужна запись перед переиспользованием),
`FREE`. Закреплённые не стоят ни в одной. Возврат идёт по классам, внутри
класса — по очередям.

## Чего мы сознательно не строим

Суперстраницы, NUMA, раскраску страниц, сжатие памяти, слой зон уровня `uma`.
Это то, за что FreeBSD и XNU платят сложностью ради нагрузок, которых у нас
нет. Каждый пункт можно будет добавить потом; ни один не является
предпосылкой для остального.

## Порядок работ

Не «выключили старое, пишем новое». Ядро сейчас живое, контрактный набор
проходит, есть два измерителя. Новые структуры вводятся рядом, точки вызова
переносятся, старое удаляется. От старого кода не останется ничего, но если мы
ошиблись в проекте, это выяснится на втором этапе, а не на восьмом.

| этап | содержание | чем проверяется |
|---|---|---|
| 1 | `vm_page` — массив на кадр, поглощает `pmm_page_desc` и боковую `vm_page_ref` | **сделано**, см. ниже |
| 2 | физический аллокатор на приятелях поверх `vm_page` | **сделано**, см. ниже |
| 3 | `pmap_t` — контракт, реализация amd64, вынос 37 обращений из `mm/` | **сделано**, см. ниже |
| 4 | `vm_object` с разрежённым индексом и своим замком | **сделано**, см. ниже |
| 5 | `vm_map` сортированный, без потолка, спящий замок на карту | **сделано**, см. ниже |
| 6 | путь отказа поверх всего этого | **сделано**, см. ниже |
| 7 | классы, очереди, закрепление, предварительное отображение | **сделано**, см. ниже |
| 8 | возврат памяти по классам, учёт, уведомления, убийство по полосам | **сделано**, см. ниже |

Этап 2 стоит рано намеренно. Ограниченное сверху время выделения страницы —
не аккуратность, а то же самое требование, что и всё остальное в этом
документе: поток реального времени не может ждать память неограниченно долго.

## Этап 1 — сделано

`mm/vm_page.h`, `mm/vm_page.c`. Восемь байт на кадр: счётчик ссылок,
счётчик закреплений, очередь, зона. Физический адрес не хранится — выводится
из индекса.

**Что поглощено.** Боковая таблица `vm_page_ref` была односвязным списком с
линейным поиском и выделением из кучи на каждую страницу — на пути отказа и
без блокировки. Стало обращение по индексу и атомарный счётчик: поиска нет,
выделения нет, значит отказ больше не может провалиться из-за нехватки памяти
на описание страницы, которая уже существует.

**Что нашлось по дороге, и это важнее самой правки.** Массив дескрипторов
создавался только если помещался в первые 16 МБ. На нашей же тестовой машине
он ложится на 0x16ae000 — то есть **не создавался никогда**. Весь код под
`if (index < pmm_state.pages_count)` не исполнялся ни разу за всё время жизни
системы, и счётчики по зонам стояли в нуле.

Теперь они считают, и арифметика проверяема:

```
[pmm] 261600 pages managed, 2043 KiB of page state at 16ae000
[pmm] zone low    total=3840   free=3840   used=0
[pmm] zone normal total=257760 free=257241 used=519
```

3840 + 257760 = 261600. Занято 519 страниц — это 2043 КиБ массива плюс 32 КиБ
битовой карты. Сходится.

**Отказ вместо продолжения.** Раньше отсутствие массива было переживаемо:
счётчики ссылок жили в боковой таблице, работавшей независимо. Теперь они живут
в массиве, поэтому без него никто не считает ссылки, ничто не освобождается, и
машина умирает от утечки в другом месте. Загрузка останавливается с указанием,
чего именно не хватило. При восьми байтах на страницу массив это память/512,
то есть предел достижим где-то за парой сотен гигабайт — и чинить тогда надо
размер прямого отображения, а не эту проверку.

**И одна настоящая ошибка, моя.** Запасной путь `pmm_init` — тот, что работает
без карты памяти от загрузчика — не выставлял `freelist_live`. После перевода
резервирования на инкрементальное сопровождение это значило, что там оно не
работает вовсе: страницы помечались занятыми в битовой карте и оставались в
списках свободных, то есть аллокатор раздавал бы зарезервированное. Путь не
исполняется на нашей конфигурации, поэтому не всплыл ни в одном прогоне.

Массив при этом **меньше** прежнего: 8 байт против 16, 2 МБ против 4 на
гигабайт, и несёт больше.

## Этап 2 — сделано

`mm/vm_phys.h`, `mm/vm_phys.c`. Аллокатор машинно-независимый и живёт в `mm/`
по той же причине, что и у FreeBSD (`sys/vm/vm_phys.c`): решать, какие кадры
свободны, — вопрос про кадры и ни про что больше.

**Что убрано.** Массив из 128 диапазонов на зону, молча терявший всё сверх
этого; обход всей битовой карты, когда диапазоны переставали описывать
достаточно памяти; и перестройка всех списков после него. Дважды O(всей
памяти) ради одной страницы, с выключенными прерываниями.

Битовая карта убрана целиком. «Свободна ли страница» теперь отвечает сам
аллокатор — поиск блока, покрывающего страницу, ограниченный числом порядков.
Один источник истины вместо двух, которые могли разойтись.

**Кодировка.** Порядок хранит только голова блока; у всех прочих страниц он
равен `VM_NFREEORDER`. Поиск идёт вверх по выровненным основаниям, что
ограничено числом порядков и снимает необходимость помечать хвосты — иначе
освобождение блока в 16 МБ стоило бы четырёх тысяч записей. Это кодировка
FreeBSD (`vm_phys_unfree_page`), и взята она потому, что вопрос тот же.

**Что измерено, и чем.** Не временем: наши часы под эмулятором уже уличены в
том, что показывают двенадцать секунд там, где тик таймера не сдвинулся ни
разу. Считаются операции — они детерминированы и эмулятору не подвластны.

`rdnx.vmphys=selftest`, четыре фазы: работа на целой памяти, фрагментация
освобождением каждой второй страницы, та же работа поверх фрагментации, и
возврат всего обратно.

```
[vm_phys] selftest: 512 pages, 256 free blocks in the way;
          splits 1 whole -> 1 fragmented; merges 1 / 1 / 3 deep;
          bound 12; free 248003 -> 248003
```

Разбиений столько же при 256 мешающих блоках, сколько на целой памяти. Это и
есть утверждение этапа. Слияние доходит до глубины 3 при пределе 12, счёт
свободных страниц возвращается ровно. Тест паникует, если предел превышен,
если страницы потерялись — и **если слияние не сработало ни разу**, потому что
непроверенная граница границей не является.

**И одна ошибка, найденная тестом до коммита.** Первая версия проверяла предел
на *вызов*, а не на *блок*, и упала на массовой отдаче памяти при загрузке: 72
операции. Ошибкой было утверждение, а не аллокатор — пробег в четверть
гигабайта раскладывается на шестьдесят с лишним блоков по 16 МБ, и это
пропорционально памяти совершенно правильно. Ограничен блок; пробег ограничен
не был и не должен быть.

**И вторая, найденная измерителем задержек.** Постраничное изъятие диапазона
для буддийского аллокатора — неверный алгоритм: чтобы вынуть одну страницу, он
дробит блок в 16 МБ на двенадцать, и пять тысяч раз подряд это дороже, чем то,
что заменялось. Замер показал 1179 мкс против 310 у прежнего кода. Изъятие
переписано поблочно (`vm_phys_unfree_range`): каждый пересекающийся блок
снимается один раз, части вне диапазона возвращаются сразу. После этого **pmm
исчез из отчёта гигиены полностью** — ни одного превышения.

**Размеры.** `pmm.c` 1409 → 983 строк; добавилось 476 строк аллокатора и 157
страничного слоя. Состояние на страницу выросло с 8 до 20 байт — за связи в
списках свободных, двусторонние, потому что слияние снимает соседа из середины
списка, а односторонний список сделал бы это обходом и вернул бы в
единственный путь, ради которого этап затевался, неограниченный член.

## Этап 3 — сделано

`mm/pmap.h` — договор, `kernel/arch/x86_64/pmap.c` — его x86-сторона.

**Границу делает форма типов, а не соглашение.** Адресное пространство
приходит непрозрачным `pmap_t`, а не физическим адресом корня таблиц. Права
приходят как `vm_prot_t`, а не готовыми битами записи. Верхний слой физически
не может собрать запись x86 — а до этого собирал, в тридцати семи местах.

**37 → 0.** Ни одного упоминания `PTE_*`, `paging_*` или `pml4` в `mm/`, и
заголовок `arch/paging.h` оттуда больше не включается.

**Единственное место, где намерение превращается в биты** — `pmap_pte_bits()`.
Двенадцать площадок, собиравших `PTE_PRESENT | PTE_USER | PTE_RW`
самостоятельно, каждая должна была знать, что запись это бит 1, а запрет
исполнения — бит 63, и каждая была в одной правке от того, чтобы оказаться
неверной на машине, где это не так.

**Замок переехал внутрь `struct pmap`.** Был один спинлок на все адресные
пространства сразу — два процессора, обрабатывающие отказ в несвязанных
процессах, стояли в очереди друг за другом без всякой причины. У FreeBSD этот
замок лежит там же и зовётся `PMAP_LOCK`.

Заодно переведены потребители за пределами `mm/`: `task->address_space` стал
`pmap_t` вместо `void*`, в котором на самом деле лежал `pml4_phys`; загрузчик
ELF перестал собирать биты записей; планировщик перестал сравнивать CR3 —
теперь он говорит `pmap_activate()`, а во что это обходится, решает pmap.

Единственное, что архитектура знает о своём же `pmap` снаружи —
`pmap_x86_root()` в отдельном приватном заголовке, для возврата в ring 3,
который грузит CR3 сам.

**Граница проверяется, а не запоминается.** `make check-mm-boundary` падает,
если в `mm/` появится что-то, что может значить только одна машина.
Фальсифицировано: вписанный обратно `PTE_PRESENT` роняет проверку.

Проверка, которую делают один раз, границей не является — ровно так и
накопились те тридцать семь.

## Этап 4 — сделано

`vm_object` переписан: разрежённый индекс вместо плотного массива, свой
замок, атомарный счётчик ссылок, класс обслуживания в структуре.

**Что было.** Массив физадресов размером в потенциальный объект,
выделяемый при создании: гигабайтный mmap стоил два мегабайта таблицы при
нуле резидентных страниц. Замка не было; счётчик ссылок был обычным
инкрементом.

**Что стало.**

- **Индекс платит за фактическую резидентность.** Хеш по pindex:
  корзины — массив индексов `vm_page`, цепочки продеты сквозь сами
  страницы (`vm_page.obj_next`). Вставка не выделяет памяти никогда —
  узел индекса и страница суть одно, как лист radix-дерева у FreeBSD.
  Отказ не может провалиться из-за нехватки узла для страницы, которая
  уже существует, — то же свойство, ради которого этап 1 поглотил
  `vm_page_ref`.
- **Рост амортизирован.** Корзины появляются при первой вставке (объект
  без страниц не стоит ничего), растут вчетверо при факторе загрузки 2;
  новая таблица выделяется вне замка, перенос ограничен числом
  резидентных страниц.
- **`vm_page` знает владельца.** Поля `object`/`pindex` — это заготовка
  этапов 7–8: очередям возврата и обратным отображениям нужен ответ «чья
  это страница», и теперь он в самой странице.
- **Свой замок.** Пока весь VM ходит под глобальным `vm_lock`, он
  дублирует защиту; нагрузку примет на этапах 5–6, когда `vm_lock`
  умрёт. Порядок: замок объекта → замок кучи (рост), ввод-вывод под ним
  не делается.
- **Инвариант «страница резидентна не более чем в одном объекте»
  охраняется детекторами**, печатающими безусловно: перевставка страницы
  с ненулевым `object` (перешивание чужой цепочки — след двойного drop)
  и освобождение страницы, оставшейся в индексе. Оба молчат на всём
  контрактном наборе.

API не менялся: `create/ref/unref/get_resident_page/set_resident_page` —
потребители (vm_map, vm_fault, posix mmap) не тронуты. Страницы наружу
пока отдаются физадресами; переход на `vm_page_t*` в сигнатурах — вместе
с путём отказа (этап 6).

Проверено: UP ALL PASS, серии `-smp 2`/`-smp 4` контрактного набора.
Замечен редкий сбой CT-029 (код возврата `ls`, машина жива) — один на
десятки прогонов, воспроизводится и на дереве до этапа 4; вынесен в
отдельное расследование, диагностика разложена по шагам
(`spawn`/`waitpid`/статус) прямо в наборе.

## Этап 5 — сделано

`vm_map` переписан: сортированный список вместо массива на 128, спящий
замок на карту, глобальный `vm_lock` умер.

**Что было.** Массив `entries[128]` с линейным перебором; `E_BUSY`, когда
процессу понадобилась 129-я запись; поиск свободного диапазона —
прощупывание адресного пространства постранично, O(диапазон × записи).
Замок — один спинлок на весь VM-слой с выключенной преемпцией, включая
fork (обход каждой страницы родителя) и путь отказа (ввод-вывод
пейджера). И дырявый: семейство `vm_task_mmap*` и `brk` его вовсе не
брали — mmap против конкурентного отказа был гонкой по массиву.

**Что стало.**

- **Сортированный список без потолка.** Записи — узлы TAILQ,
  упорядоченные по адресу; инварианты (порядок, отсутствие пересечений)
  держит вставка. Поиск и проверка пересечения обрываются на первой
  записи правее диапазона; разрез записи при частичном munmap — вставка
  хвоста сразу за текущей, сортировка сохраняется сама. Единственный
  отказ — нет памяти под запись, а не «карта кончилась».
- **`vm_find_gap` — один проход по списку**: кандидат сдвигается за конец
  каждой мешающей записи. Прежний цикл в худшем случае делал сотни тысяч
  проверок пересечения.
- **Замок на карту, спящий (kmutex).** Карты разных задач больше не
  сериализуют друг друга; ожидание не жжёт процессор; во время
  ввода-вывода пейджера процессор занят другими потоками. Спать в
  обработчике отказа законно — этот путь уже спал на Giant. Порядок:
  Giant → замок карты → внутренние спинлоки (объект, pmap, куча).
- **Все публичные входы — под замком без исключения**, включая прежде
  голые mmap/brk. Без замка остались только пути с монопольным доступом
  по построению: exec (единственный поток задачи сносит старую карту) и
  destroy (задача мертва) — там взятие kmutex карты означало бы
  освобождение удерживаемого замка вместе с картой.
- **fork берёт замок родителя**; карта ребёнка до конца вызова никому не
  видна и строится хвостовыми вставками — родитель сортирован, порядок
  наследуется даром.

Проверено: UP ALL PASS, 8/8 на `-smp 2`, 4/4 на `-smp 4` (после
исправления FXSAVE набор детерминирован — сбоев ноль).

## Этап 6 — сделано

Путь отказа переписан поверх новых структур: три фазы, у каждой свой
владелец, и одна настоящая гонка закрыта.

**Форма.** Валидация — под замком карты; разрешение страницы — объект под
своим замком, а наполнение от пейджера (ввод-вывод!) — без единого
спинлока, до публикации; отображение — pmap под своим. Ввод-вывод спит
под kmutex карты, не жжёт процессор и не держит преемпцию.

**Гонка, которую закрыла форма.** Два отказа на одной странице одного
разделяемого объекта из двух разных карт: замки карт разные, оба доходят
до объекта. Раньше там были `get` и `set` по отдельности — два процесса,
загрузившие один ELF, могли получить **две разные копии** одной страницы
файла (и жить с расходящимися отображениями разделяемого объекта). Теперь
проверка и вставка — одна критическая секция
(`vm_object_insert_or_get_page`): проигравший гонку не вставляет свою
страницу, а принимает чужую. Замещений в индексе объекта не бывает
вовсе — страница по pindex неизменна до смерти объекта, поэтому
«найти и взять ссылку» безопасно без обходных манёвров.

**Пейджер стал слоем.** Наполнение страницы содержимым файла ушло из
отказа в `vm_pager_fill_page`: путь отказа больше не роется в
`pager_private`, и единственная встреча с задником — одна функция.

**Счётчики.** `vm_fault_stats` (всего/нулевые/чтения пейджера/COW-копии/
принятые в гонке/ложные) и `thread_t.fault_count`. Это не отладка, а
измеритель обещания этапа 7: «RT-поток не берёт ни одного отказа»
проверяется числом на потоке, и поле для этого числа уже есть.

Проверено: UP ALL PASS, 8/8 на `-smp 2`, 4/4 на `-smp 4`. Гигиена
задержек: в нарушителях не осталось ни одного окна из `mm/` — все
оставшиеся принадлежат ext2 (его внутренние 2–4 мс преемпции, давний
кандидат на kmutex) и обработчику вектора 0xe0.

## Этап 7 — сделано

Классы, очереди страниц, закрепление, предварительное отображение — и
обещание, проверяемое числом.

**Очереди подкачки.** ACTIVE/INACTIVE/LAUNDRY как индексные списки поверх
`vm_page`; линки общие со свободными списками аллокатора — у страницы
всегда не больше одного владельца линков, и каждый работает под своим
замком (pmm_spin / pq_spin), различая состояния по `queue`. Каждая
установленная в отображение страница встаёт в ACTIVE; закреплённая — ни в
одной. Возврат (этап 8) получит готовые очереди с уже соблюдаемой
дисциплиной членства.

**Закрепление.** `vm_page_wire/unwire`: закреплённая страница покидает
очереди и недосягаема для будущего возврата, что бы ни случилось с
давлением. Последнее открепление возвращает её в ACTIVE.

**Классы.** Умолчание — на задаче (`vm_class_default`, явно NORMAL — ноль
в этом перечислении означает RT, и нулевая инициализация сделала бы всю
память неприкосновенной); объекты наследуют его при создании. RT-поток
повышает класс объектов, которых касается, — но это страховочная сетка,
а не норма.

**Сильное обещание.** `vm_task_mlock` приводит каждую страницу диапазона
СЕЙЧАС — той же машинерией отказа, вызванной заранее, включая разрыв COW
для записываемых отображений (иначе первая запись после mlock взяла бы
отказ, и обещание было бы ложью) — и закрепляет. Отказ RT-потока после
этого — поломка обещания, и ядро печатает его безусловно ([VMRT], с сырой
цепочкой трансляции), как XNU охраняет RT-страницы: молчаливая сетка
скрывала бы поломку.

**Сисколлы**: mlock/munlock (86/87), schedrt (88, ручка RT для теста —
настоящая ОС даст RT через сессию аудио-сервера), threadfaults (89).

**CT-043 — тест обещания, фальсифицируемый.** mmap двух буферов; RT;
mlock первого; касания всех его страниц обязаны дать **ноль** отказов
(`thread_t.fault_count` до и после); затем контрольный незакреплённый
буфер обязан отказы **брать** — иначе счётчик мёртв и зелёному верить
нельзя.

**Что поймал тест уже при рождении.** CT-043 нестабильно падал на
`-smp 2`: закреплённые страницы отказывали err=0xe (RSVD) бесконечной
серией, но только когда поток попадал на cpu1. Сырая цепочка трансляции
показала здоровый PTE — здоровый на BSP: трамплин AP включал в EFER
только LME, без NXE, и бит 63 («не исполнять»), который pmap ставит на
всякое неисполняемое отображение, на AP был зарезервированным. Та же
болезнь, что дыра с FXSAVE: инициализация BSP и AP разъезжается по
одному MSR за раз. Исправлено отдельным коммитом; тест, созданный
проверять обещание памяти, первым делом окупился, поймав дефект
процессорной инициализации.

Проверено: UP ALL PASS, 12/12 на `-smp 2`, 4/4 на `-smp 4`; [VMRT] в
логах контрактного набора — ноль строк.

## Этап 8 — сделано

Возврат по классам, учёт двумя числами, давление, убийство по полосам — и
тест, в котором аудио переживает голод.

**Возврат** (`vm_reclaim_run`) идёт по реестру объектов в порядке цены
ошибки: VOLATILE (выбросить по контракту, без ввода-вывода) → CACHE →
NORMAL-файловое с записью в задник. PROJECT и RT не трогаются. v0 берёт
только страницы, чей единственный держатель — объект (нигде не
отображены, не закреплены): отобрать отображённую честно нельзя без
обратных отображений, pv_list остаётся в открытых вопросах. Реестр
объектов с try-ref — снятие с учёта есть первый шаг разрушения, и возврат
не может разыменовать умирающий объект.

**Учёт** (`vm_task_mem_account`) — два числа на два вопроса: начисленное
(каждый держатель платит за разделяемое полностью) и освобождаемое
(последнее держание). Убийца выбирает по второму.

**Полосы** (`kernel/oom.c`): BACKGROUND → FOREGROUND → AUDIO, CRITICAL и
задачи ядра вне игры; наследуются при fork, меняются сисколлом memband.
Убийство всегда объяснено ([OOM]: полоса, освобождаемое, окно), перед
силой — SIGTERM с окном 200 мс на сброс. Протокол нехватки в отказе:
возврат → повтор → убийца → сон и снова, с терпением, соразмерным жнецу.
Неразрешимый пользовательский отказ теперь убивает процесс, а не машину
(init и ядро — в панику, как и положено).

**Тест CT-044**: трое обжор (BACKGROUND) наедаются до давления и засыпают;
родитель с закреплённым «аудио»-буфером устраивает шторм глубже
свободного остатка. Ожидаемое и наблюдаемое: убийца снимает обжору по
полосе, выделения родителя проходят, аудио-буфер — ноль отказов за весь
шторм.

**Что тест вскрыл по дороге** — пять настоящих дефектов:

1. **Вооружение таймаута ожидания без замка**: вставка в глобальный список
   таймаутов рвалась тиком посреди неё, узел терялся, спящий не просыпался
   никогда. Шторм коротких снов сделал из редкой гонки постоянную.
2. **Зомби держал память до waitpid**: жертва убийцы не освобождала ни
   страницы, пока родитель — сам стоящий в отказе за памятью — не спросит.
   Адресное пространство теперь отдаётся смертью; зомби хранит только
   статус.
3. **fork ломал обещание mlock**: COW снимал запись у родителя, и
   закреплённые страницы начинали отказывать. Закреплённое теперь
   форкается жадной копией ребёнку, PTE родителя неприкосновенен.
4. **Правка очереди готовности без rq_lock** в принудительном завершении:
   тик посреди TAILQ_REMOVE — NULL-запись ядра. Заменена честным
   `scheduler_ready_remove` под замком.
5. **Выделению страниц таблиц не полагался протокол нехватки**: pmap_enter
   при пустом аллокаторе убивал процесс мгновенно, минуя возврат и полосы.

Известное ограничение: waitpid не поддерживает WNOHANG (флаги
игнорируются) — тест использует ожидание любого ребёнка; отмечено как
отдельная работа.

Проверено: UP ALL PASS, 6/6 на `-smp 2`, 3/3 на `-smp 4`; [VMRT] — ноль
строк, [OOM] объясняет каждое решение.

## Побочная находка: зависание стало стопроцентным

Прогоны `-smp 2` после этапа 3 дали 0 из 8 при исторических ~50%. Изоляция по
коммитам:

| | проходов |
|---|---|
| до работы над часами (`e7575e8`) | 2 / 5 |
| после часов | 0 / 5 |
| + pmap | 0 / 8 |

`pmap` невиновен. Причина — исправление часов: таймауты были вдесятеро короче
запрошенного, и всякий цикл ожидания теперь ждёт столько, сколько просил, а не
десятую часть. Окно гонки изменилось полностью.

Это к лучшему. Известное зависание из перемежающегося стало детерминированным,
а детерминированный воспроизводитель отлаживается, случайный — нет.

## Открытые вопросы

- ~~Кто назначает полосу процессу~~ — решено на этапе 8: наследование от
  родителя, смена явным сисколлом (memband); умолчание — FOREGROUND.
- ~~Что делает RT-выделение при нехватке~~ — решено: mlock и есть
  резервирование при объявлении; нехватка — честный отказ в момент mlock,
  не в середине сессии.
- **Размер `struct md_page`** для amd64: список обратных отображений (`pv_list`
  у FreeBSD) нужен для `pmap_remove_all`, а тот — чтобы возврат мог
  отбирать отображённые страницы. Возврат v0 берёт только неотображённые;
  pv_list — следующий шаг возврата.
- **waitpid без флагов**: WNOHANG молча игнорируется; нужен настоящий
  разбор flags в unix_proc_waitpid.
